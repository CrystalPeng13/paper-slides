# 論文報告投影片庫

> 一篇論文進來，一份三十分鐘的報告出去。

給 AI 一篇論文 PDF，它會依照 [`CLAUDE.md`](CLAUDE.md) 的規範，產出**碩班論文報告投影片**與**閱讀筆記**，並呈現在網站上。重點不是做出某一份投影片，而是建立一套**可以反覆使用的規則**：每多一篇論文，就是照同一套流程再跑一次。

- 網站：（上傳 GitHub Pages 後填入）
- 規範：[`CLAUDE.md`](CLAUDE.md)（其他 AI 工具的入口：[`AGENTS.md`](AGENTS.md)）

## 網站內容

| 頁面 | 說明 |
|---|---|
| 目錄 | 所有報告過的論文，可搜尋、依主題篩選、排序 |
| 閱讀筆記 | 每篇論文的研究問題、方法、實驗、結果、限制、術語表、圖表一覽 |
| 投影片 | 全螢幕播放（方向鍵翻頁、`F` 全螢幕、`S` 講者模式），可匯出 PDF |
| 術語表 | 自動彙整所有論文的術語，確保整個投影片庫用詞一致 |
| 關於 | 說明這套規範：七個步驟、四個面向、十二種頁面類型 |

## 這套規範怎麼讓 AI 繼續做下去

1. **固定流程**：收件 → 精讀寫筆記 → 擬大綱（⛔ 停下來等使用者確認）→ 擷取圖表 → 寫投影片 → 自動檢查 → 交件。
2. **固定結構**：30 分鐘報告固定 14 個章節、26～32 頁；12 種頁面類型各有語法範例；`templates/paper/` 是 29 頁的標準骨架。
3. **內容與程式分離**：新增論文只要在 `content/` 多一個資料夾，網站會自動讀到，不必改任何程式。
4. **規範寫進程式**：頁數、條列上限、必填欄位、大陸用語對照都定義在 `src/lib/rules.ts`，`npm run check` 會自動檢查，違規就無法建置。
5. **情境導覽**：`CLAUDE.md` §0.1 告訴 AI「新增論文」「修改網站」「修改規範」各要讀哪幾節、能改哪些檔案、做完要跑哪份檢查清單。

## 使用方式

```bash
npm install            # 安裝套件
pip install pymupdf    # PDF 工具需要
npm run dev            # 本機預覽 http://localhost:5173/
npm run check          # 檢查所有論文是否符合規範
npm run build          # 內容檢查 → 型別檢查 → 建置到 dist/
```

新增一篇論文：把 PDF 放進 `papers/`，告訴 AI「幫我做這篇論文的報告，報告日期是 YYYY-MM-DD」，AI 會依照 `CLAUDE.md` §4 完成。

## 版權

論文圖表的版權屬於原作者，網站中每張圖表都有標示來源。論文 PDF 原檔不會上傳（見 `.gitignore`）。
